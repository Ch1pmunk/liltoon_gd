# 从 lilToon 迁移到 liltoon_gd

本文面向已经在 Unity 里用 lilToon 做过材质、现在要在 Godot 里重建的人。

## 先确认两件事

**1. 渲染器必须是 Forward+**

```
Forward+            完整功能（后处理描边、法线粗糙度纹理）
Mobile              后处理描边关闭、法线纹理不可用
Compatibility       主材质无法编译（67 个 sampler2D 超过 16 个纹理单元）
```

**2. 主材质有 67 个采样器**

这意味着即便在 Forward+ 下，"多材质 + 多光源"的场景初始化开销很大。弱机上可能触发驱动超时（TDR），表现为启动即黑屏。这是引擎层的限制，与参数无关。

## 三条迁移路径

### 路径一：Godot 标准材质 → liltoon_gd

适用：原本就不是 lilToon 材质，想换成卡通渲染。

```gdscript
# 编辑器里：选中 StandardMaterial3D 材质 → 工具栏 liltoon → 转换
# 代码里：
var mat := LiltoonTools.convert_standard_material(src)
```

**实际映射的 25 个参数**（超出这个范围的一律不转，需要手动调）：

```
main_color / main_texture / main_uv_scale / use_vertex_color
normal_texture / normal_strength / use_normal_map
emission_color / emission_intensity / emission_texture / use_emission_texture
metallic / roughness / use_reflection
ao_texture / ao_light_affect / use_ao_map
rim_intensity / use_rim
sss_color / sss_strength / use_sss
alpha_cutoff
```

**会丢失**：所有 lilToon 特有的卡通参数（阴影色、边界、MatCap、Glitter、贴花、描边等）。转换只是"起点"，卡通效果要自己调。

### 路径二：lilToon 预设（Unity `.asset`）→ 材质

适用：已有 lilToon 材质，想尽量原样搬过来。

```gdscript
# 编辑器里：工具栏 liltoon → 导入预设
# 代码里：
var parsed := LiltoonPresetImport.parse_file("res://xxx.asset")
var warnings := LiltoonPresetImport.map_to_material(parsed, mat)
```

工作原理：解析 Unity YAML 的 `colors` / `vectors` / `floats` 段，按名称表映射到本插件的参数，**只写目标材质真实存在的参数**，无法映射的会在返回值里列出。

**实测覆盖率**：`ALIASES` 里有 127 条手工别名，配合蛇形命名自动匹配，合计覆盖 296 个 lilToon 属性（占 578 项的 51%）。剩下的见第四节。

**注意**：贴图不会被导入（Unity 的 GUID 在 Godot 里无效），需要手动挂。

### 路径三：手动重建

复杂材质（多槽 MatCap + 贴花 + 毛发）建议直接照 lilToon 的 Inspector 重调。参数名基本一一对应，查 `docs/参数对齐矩阵.md` 即可。

## 参数对照怎么查

`docs/参数对齐矩阵.md` 是唯一的权威表，分两张：

- **已对齐 296 项**：左边是 lilToon 属性名，右边是本插件参数名
- **未对齐 282 项**：按类别列出，每条都注明为什么不做

常用对照举例：

| lilToon | 本插件 | 备注 |
|---|---|---|
| `_Color` / `_BaseColor` | `main_color` | |
| `_MainTex` / `_BaseMap` | `main_texture` | 需同时开 `use_main_texture` |
| `_BumpMap` | `normal_texture` | 需同时开 `use_normal_map` |
| `_ShadowColor` | `shade_color` | |
| `_ShadowBorder` | `shade_threshold` | |
| `_ShadowBlur` | `shade_blur` | |
| `_MatCapTex` | `matcap_texture` | 需同时开 `use_matcap` |
| `_RimColor` | `rim_color` | |
| `_OutlineWidth` | `outline_width` | 描边是 `next_pass` 材质 |
| `_Cutoff` | `alpha_cutoff` | |

**命名规则**：lilToon 的 `_MatCapBlendUV1` → `matcap_blend_uv1`（去下划线前缀、驼峰转蛇形、`MatCap` 合并成 `matcap`）。大多数参数可以按这个规则直接猜。

## 不支持的能力（282 项的四类）

### 1. Unity 渲染状态（约 59 项）

`_BlendOp` / `_SrcBlend` / `_ZTest` / `_Stencil*` / `_Cull` / `_OffsetFactor` 这类。
Godot 里由 `render_mode` 和材质属性控制，不可能做成 shader 参数。

### 2. Unity 专有功能（约 64 项）

| 功能 | 为什么不做 |
|---|---|
| ID 遮罩 28 项 | Unity 的 `_UDIMDiscard` / 遮罩系统，Godot 无对应 |
| AudioLink 21 项 | 依赖音频总线与频谱分析，需要单独的运行时模块 |
| Tessellation 4 项 | Godot 4 无曲面细分 |
| HDRP 专属 6 项 | `_lilDirectionalLightStrength` 等只在 HDRP 分支定义 |
| Parallax 5 项 | Godot 没有 Unity 的视差映射节点 |

### 4. 独立 shader 系列（43 项）

lilToon 除主材质外还有三条独立功能线，**本项目未实现**：

| shader | 属性 | 状态 |
|---|---|---|
| `lts_ref`（折射） | `_RefractionColor` / `_RefractionColorFromMain` / `_RefractionStrength` / `_RefractionFresnelPower` | 未实现，可做（屏幕采样 + UV 扰动） |
| `lts_gem`（宝石） | `_GemChromaticAberration` / `_GemEnvColor` / `_GemEnvContrast` / `_GemParticleColor` 等 8 项 | 未实现，4 项可做 |
| `lts_fakeshadow`（假阴影） | `_FakeShadowVector` | 未实现，可做 |
| `lts_overlay`（叠加层） | 30 项 `_Pre*` 渲染状态 | 不做，Unity 专属 |

### 3. 引擎差异导致的硬限制（约 16 项）

| 项 | 原因 |
|---|---|
| `_ReflectionCube*` 8 项 | Godot 的 ReflectionProbe 不通过材质参数工作 |
| `_ReflectionBlendMode` | 引擎反射混合固定为加法 |
| `_ReflectionColor` | `SPECULAR` 是标量，无法染反射色（我们提供 `reflection_color_tex` 做标量亮度近似） |
| `_RimBlendMode` | 原版在最终颜色上按 Normal/Add/Screen/Multiply 混合，Godot 的 `light()` 只能累加 |
| `_Anisotropy2Reflection` | 没有独立反射法线 |
| `_MatCapZRotCancel` | 需要角色空间法线，与我们的视空间实现语义冲突 |
| `_VRParallaxStrength` | VR 专用 |

## 已知差异（会影响外观）

**1. 反射整体偏弱**

Godot 的 `SPECULAR` 是标量，无法按通道染色，也无法用法线扰动。金属度低时差异不明显，金属度高时需要手动补环境贴图。

**2. 后处理描边在当前环境不生效**

`depth_texture` 采样恒为 0（已记 RISKS）。网格描边（`next_pass`）不受影响，可以用它替代。

**3. 毛发是 MultiMesh 叠壳，不是几何着色器**

层数由 `fur_layers` 控制（1–12），层数少时壳层之间会露出发根。原版用几何着色器生成，密度更高。

**4. MatCap 的受光走 `light()`**

`matcap_enable_lighting` 非 0 时，MatCap 从 `fragment()` 搬到 `light()` 逐光源累加。结果正确，但**多光源会重复采样**，开销随光源数线性增长。该参数默认 1（与原版一致），如果不想要受光可设为 0。

**5. 默认不接收引擎阴影**

`shadow_receive` 默认 0（与原版 `_ShadowReceive` 一致）。如果发现物体的实时阴影不显示，检查这个参数。

## 排查

| 现象 | 先查 |
|---|---|
| 物体全黑 | `main_color` 是否接近黑；`use_unlit` 是否误开 |
| 材质完全不显示 | 渲染器是否 Forward+；是否 Compatibilty 下的采样器超限 |
| 启动即黑屏 / 闪退 | 场景材质数 × 光源数过多，初始化超过 2 秒触发 TDR（弱机） |
| 调了参数没反应 | 查矩阵该参数是否标记为"已对齐"；`use_*` 开关是否打开 |
| 贴图导入后是空 | Unity 的 GUID 无法映射，需要手动挂贴图 |
| 阴影没有 | `shadow_receive` 默认 0；或 `use_shadow` 未开 |
