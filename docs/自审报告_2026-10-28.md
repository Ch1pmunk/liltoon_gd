## 二、发现的问题（均已修复）

### 1. 预设漏项 5 个

`BASE` 里有 `shade_blur`（第一层），但没有第二、第三层的柔化，切换预设时 2nd/3rd 的柔化不会被重置。

| 漏项 | 默认值 | 处理 |
|---|---|---|
| `shade_2nd_blur` | 0.05 | 补进 `BASE` |
| `shade_3rd_blur` | 0.05 | 补进 `BASE` |
| `outline_mask_threshold` | 0.5 | 补进 `OUTLINE_KEYS` |
| `outline_mask_uv_scale` | (1,1) | 补进 `OUTLINE_KEYS` |
| `outline_shade_color` | (0.35,0.35,0.35,1) | 补进 `OUTLINE_KEYS` |

这类问题冒烟抓不到——它只检查"有没有登记"，不检查"登记得全不全"。

### 2. 第三槽 MatCap 是扩展，不是对齐项

`matcap_3rd_apply_transparency` / `_backface_mask` / `_perspective` 三项在文档里从未说明来历。查 lilToon 源码确认：**原版只有 `_MatCap` / `_MatCap2nd` 两槽，不存在 `_MatCap3rd*`**。

第三槽是本项目"顺手实现"的额外能力，按原则属 A 类：保留、不深入、不参与对齐计数。已写进 §9。

### 3. 两项映射错误（且我自己先补重复了）

`_Shadow2ndNormalStrength` / `_Shadow3rdNormalStrength` 在矩阵里登记过，但目标写的是通用的 `shade_normal_strength`。实际代码里是独立的 `shade_2nd_normal_strength` / `shade_3rd_normal_strength`。

我第一次处理时没查重，直接在表尾又加了两行，造成同一属性出现两次。后发现并修正映射、删掉重复行。**这类"补文档反而引入重复"的问题，靠肉眼很难察觉，是交叉校验（`audit_consistency.py` 报 282 vs 脚本报 280）才暴露的。**

### 4. 矩阵统计曾长期失真

旧口径 `277 未对齐` 由三处误差叠加：属性基线虚高 36（`_e2ga0` 这类表情动画占位被当成材质参数）、21 项已实现未登记、12 项命名差异误判。现由脚本重算，且脚本自身修了 5 个 bug（`re.MULTILINE` 缺失、缩写拆分、`2nd` 位置、sampler 未排除、数组形式预设键未识别）。

## 四、这次自审查不了什么

必须说清楚，避免留下"已全量验证"的错觉：

1. **画面是否与原版一致** —— 完全没有验证。所有 shader 只保证"能编译"，不保证"长得对"。
2. **数学是否逐像素等价** —— 只能保证公式对着源码抄，无法保证边界条件（`pow` 的 0 次幂、法线退化、除零）在所有输入下都不出问题。
3. **需要实机观察的行为** —— A2C 的裁切质量、毛发壳层排序、后处理描边在移动端的降级提示、ReflectionProbe 不生效的现场表现。
4. **性能** —— 除了三次基准（`quality_lab`）和毛发帧率，没有系统性测量；新增的逐光源累加路径（MatCap/Glitter 受光）开销未测。

这些都需要渲染环境。本机目前可以渲染（单次、间隔 30 秒、连续 5–10 次后静默几分钟），但属"有限额度"，见 `ROADMAP.md` RISKS。

# 追加：P9 产出自审（2026-10-28 晚）

P9 做完后没有立即自审，是被提醒后补的。结果抓出 6 类问题，其中 3 类是**改类型引发的连锁失效**——这类问题不会报错，只会让功能悄悄失灵。

## 1. `.tscn` 里的过时参数值（12 处）

P9 把 `shadow_receive` / `rim_enable_lighting` / `rim_shadow_mask` 从 bool 改成 float 程度值。场景文件里硬编码的旧值无法转换，Godot 会静默拒绝：

```
feature_lab.tscn    shadow_receive / rim_shadow_mask / matcap_main_strength 各 2 处 = null  → 删行，改用默认值
quality_lab.tscn    shadow_receive = true ×2 → 1.0；rim_shadow_mask = false ×2 → 0.0
character.tscn      rim_enable_lighting = true ×2 → 1.0
```

**如果不修**：这些场景的对应参数会停在 shader 默认值，行为与作者意图不符，且日志无任何提示。

## 2. `rim_lab.gd` 传 bool 给 float 参数

函数签名 `_make_material(..., enable_lighting: bool, indir: bool)`，直接 `set_shader_parameter` 到 float 参数会失配。已改为显式转换 `1.0 if x else 0.0`，保留原有 bool 签名以免动调用点。

## 3. 迁移指南引用的类名不存在

| 文档写的 | 实际 |
|---|---|
| `LiltoonMaterialTools.convert_standard_material` | 在 `LiltoonTools` 里 |
| `LiltoonPresetImport.parse_file` | 该类当时**没有 `class_name`** |

前者改文档，后者给 `liltoon_preset_import.gd` 补上 `class_name LiltoonPresetImport`（其他编辑器脚本都有，唯独它漏了）。

## 4. 文档数字错误（5 处）

```
采样器  66 → 67      迁移指南 2 处、README 2 处
映射表  128 → 127    （删掉 speculartex 后少一条）
```

顺带把"128 条映射能对上 280 个属性"改准确了——127 是手工别名数，280 是"手工别名 + 蛇形自动匹配"的总覆盖，两者不是一回事。

## 5. `plugin.cfg` 描述误导

原写"MatCap **三槽**"，但原版只有两槽，第三槽是本项目扩展。已改为"MatCap"，避免让人以为三槽也是对齐项。

## 6. 语义漂移（未修，已记录）

`quality_lab.tscn` 里 `matcap_main_strength = 1.0`：
- 旧语义（强度系数）→ 强度拉满
- 新语义（乘主色程度）→ 完全乘主色

该场景是 bench 工具，外观差异不影响用途，未改。但"默认值语义变了、旧数据含义随之改变"这类情况，发布说明里应提示。

## 验证方式

```
冒烟                 3.6 秒通过
headless 加载场景    feature_lab / quality_lab 均 0 错误
check_all_shaders    -ListOnly 正常
```

**headless 加载是关键手段**：它不创建渲染设备、不会触发 TDR，却能验证"场景结构没被删行破坏"。

## 教训

**改参数类型是有破坏性的**，影响面包括：shader 声明、`light()`/`fragment()` 实现、预设字典、`.tscn` 里硬编码的值、`.gd` 里的传参类型、文档中的示例代码。P9 只改了三处声明，但连带改了 12 个场景值 + 1 个脚本传参 + 2 处文档 API。

**这类连锁失效必须靠"全仓搜参数名"来查**——冒烟只校验"参数有描述、进预设"，不校验"场景里的旧值还能不能转换"。

## 发现但未修的一项

**`effects/` 下的两个后处理 shader 不在编译验证范围内。**

`tools/compile_check.gd` 的 `SHADER_DIR` 固定为 `res://addons/liltoon_gd/shaders/`，而 `post_outline_screen.gdshader` / `post_outline_screen_basic.gdshader` 在 `effects/` 下。也就是说这两个 shader **从未进入过编译自检**，一直是靠 `outline_lab` 场景实际运行来间接验证的。

修它需要扩大扫描目录并重新跑一轮编译验证，属于渲染操作，暂缓。已记入本节，下次有渲染额度时先做这个。

## 这一轮查不出什么

必须说清楚：

1. **视觉正确性** —— 完全没查，静态审计无法判断"画得对不对"
2. **shader 数学的边界行为** —— `pow(0,0)`、法线退化、极端参数组合，只有实际渲染才暴露
3. **运行时交互** —— Inspector 的拖拽、撤销重做、批量操作的实际手感
4. **性能** —— 逐光源累加的真实开销、465 参数材质的初始化时间
5. **跨渲染器行为** —— Mobile / Compatibility 下的实际降级表现

这五项都要 GPU。
