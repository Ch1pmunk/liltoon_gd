## 一、一句话现状

`liltoon_gd` 是一个 Godot 4 的卡通渲染插件，按 Unity 的 [lilToon](https://github.com/lilxyzw/lilToon) 对齐。**代码功能已到 v1.0，但对齐不完整、视觉验证不足、且有明确的功能遗漏**——三项都不是"没时间做"，而是这台开发机跑不动渲染。

## 四、原 15 项「可做但未做」——2026-10-29 已全部补齐

**2026-10-29 更新**：15 项已全部实现并有截图证据（`docs/evidence/阶段9/`）。矩阵对齐从 296 升至 307。

以下为原始记录（保留供追溯）：

### 折射（4 项）

```
_RefractionColor          折射颜色
_RefractionColorFromMain  用主色作折射色
_RefractionStrength       折射强度
_RefractionFresnelPower   折射菲涅尔幂
```

**实现思路**：`hint_screen_texture` 采样屏幕 + 按法线扰动 UV。Godot 支持，约半天。
**注意**：本项目 shader 里 `hint_screen_texture` 从未使用过，要从零接。

### 宝石（4 项）

```
_GemChromaticAberration  色散（RGB 三通道分离采样）
_GemEnvColor             环境色
_GemEnvContrast          环境对比度
_GemParticleColor        粒子色
```

**不做**：`_GemParticleLoop`（需粒子系统联动）、`_GemVRParallaxStrength`（VR 专用）。
**注意**：宝石是独立 shader（`lts_gem.shader`），我们没有对应变体。要不要为它单独开一个 shader 需决策。

### 假阴影（1 项）

```
_FakeShadowVector   用平面贴图在地面画假阴影，与光照无关
```

**实现思路**：`lts_fakeshadow.shader` 只有 36 个属性，是个极简 shader。可以做一个独立的 `liltoon_fakeshadow.gdshader`，约半天。

### 毛发（6 项）

原版 `_Fur*` 去掉渲染状态后共 17 项，我们实现 11 项，缺：

```
_FurMask                 毛发遮罩（控制哪里长毛）
_FurNoiseMask            噪声遮罩
_FurRandomize            毛向量随机化（打散整齐感）
_FurVectorTex            毛向量贴图（用贴图指定方向）
_VertexColor2FurVector   顶点色转毛向量
_FurTouchStrength        触摸交互（需运行时脚本配合）
```

**为什么漏**：我们对照的是 `lts.shader` 里的 `_Fur*` 段（只有部分），没对照 `lts_fur.shader` 的完整定义。

**不算缺失**：`_FurLayerNum` 对应我们的 `fur_layers`；`_MatCapMul` 对应 `matcap_multiply`。

## 五、Editor 工具缺失（4–5 个模块）

lilToon 有 46 个 Editor 脚本（约 800 KB），我们对应实现较少：

| 模块 | 原版大小 | 我们的状态 | 价值 |
|---|---|---|---|
| Inspector GUI | ~300 KB | 有简化版（555 行） | 够用 |
| `lilToonSetting`（全局设置） | 95 KB | **没有** | 中：统一默认值、性能档、语言 |
| `lilShaderContainerImporter` | 80 KB | 不需要 | 我们直接分发源码 |
| `lilMaterialUtils` | 39 KB | 部分有 | 够用 |
| `lilEditorTextureBaker`（纹理烘焙） | 38 KB | **没有** | **高**：把多张贴图烘成一张，弱机上能省采样 |
| `lilMaterialConvertUtility` | 29 KB | 有 | — |
| `lilToonPreset` | 28 KB | 有 | — |
| `lilLanguageManager`（多语言） | 19 KB | **没有** | 低：目前仅中文 |
| `lilOptimizer`（材质优化器） | 16 KB | **没有** | 中：分析材质给优化建议 |

**资源**：官方预设（`Cloth-*` / `Hair-*` 等 `.asset`）**可以导入**，`liltoon_preset_import.gd` 支持；噪声/抖动贴图用程序生成替代，可接受。

## 六、为什么本机做不了渲染验证

开发机是 2018 年的 MacBook Air（Windows IoT LTSC）：

```
CPU/GPU   Intel UHD Graphics 617（核显）
显存      独立 128 MB + 共享 4 GB（从 8 GB 系统内存借）
屏幕      2560×1600 Retina
驱动      31.0.101.2145（2026/9），WDDM 2.7
```

**症状与已定位的规律**：

| 现象 | 数据 |
|---|---|
| `0x139` 蓝屏（内核链表损坏） | 6 次，2026-10-27 起 |
| TDR（驱动超时恢复，事件 4101） | 16 次，全部集中在 2026-10-28 |
| `0x887A0005`（DEVICE_REMOVED） | 多材质场景、溶解场景必现 |
| 崩溃阈值 | 单次渲染约 60 秒；或连续 5–10 次进程 |
| 空场景 | TDR 零增加 → **硬件没坏** |
| WHEA 硬件错误 | **0 条** |

**已排除的假设**：不是内存泄漏（内核池稳定）、不是特定 shader（单跑通过）、不是驱动版本（换过两个大版本）、不是"60 秒阈值"（`--quit-after 1` 也会崩）。

**当前判断**：多材质 + 多光源场景的**初始化阶段**（11 个材质 × 465 参数 × 4 光源串行编译）超出 2 秒 TDR 阈值。`character.tscn` 是典型受害者：579 KB、29 个 sub_resource、启动后全黑。

**关键教训**：**命令行走场景"无报错"不等于"有画面"**。黑屏不产生任何日志，我两次误判 `character` "通过"。

## 十、踩过的坑（避免重蹈）

| 坑 | 现象 | 教训 |
|---|---|---|
| **无报错 ≠ 有画面** | `character` 两次测试"通过"但全黑 | 命令行跑场景必须截图或人工确认 |
| **改参数类型有连锁破坏** | bool→float 后，12 处 `.tscn` 硬编码值静默失效 | 全仓搜参数名，不只看 shader |
| **统计口径会窄** | 只对照 `lts.shader`，漏了 98 项特有属性 | 统计前先确认"全量"的边界 |
| **补文档可能造重复** | 给矩阵补行时没查重，同一属性出现两次 | 补完跑交叉校验脚本 |
| **冒烟会卡死** | 依赖脚本编译失败后仍继续执行，进程挂 5 分钟 | 一律用 `smoke.ps1`（120 秒硬超时） |
| **凭片段下结论** | 看 grep 片段判定"除零 bug"，实际代码有保护 | 结论必须基于实际读取的完整行 |
| **测试设计本身有缺陷** | 白光测 `enable_lighting`（恒等于无效）、高频噪声测 LOD（降采样成平均灰） | 看不出差异时，先怀疑测试方法 |
| **默认值凭印象** | 声称"`_MatCapEnableLighting` 原版默认 0"，实际是 1 | 默认值必须用脚本对照源码 |

## 十二、如果要继续做，建议的顺序

1. **换机验证环境**（第 1–3 步，半天）
2. **补 15 项遗漏**（3 天，必须看画面）
3. **补 Editor 工具**（`TextureBaker` 优先级最高，弱机上能省采样；其余可选）
4. **P10 AudioLink**（21 项，单独成阶段，价值取决于目标用户是否做 VTuber/音乐可视化）

**不建议**：在验证环境之前动架构（比如按功能拆 shader 变体）。虽然那能降低初始化负担，但会打乱现有 296 项对齐的验证基线。
