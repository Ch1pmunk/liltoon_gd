## 三、执行约束（来自四次蓝屏）

```
2026-10-27  14:48 / 16:06 / 16:56 / 20:5x   0x139 (1=3)
2026-10-28  15:54                          0x139 (1=3)
```

最后一次**只连续跑了 7 次渲染进程就崩**，阈值不稳定。因此：

1. 每次只跑 **1 个场景**，间隔 ≥30 秒
2. 连续 3 个后**必须静默 5 分钟**再继续
3. 每次跑之前确认没有未保存的东西
4. 一旦蓝屏，**立即停手汇报**，不重试

## 四、执行顺序

按「风险从低到高」：

1. `shadow_full_lab`（单场景，已建好）
2. `dissolve_lab`
3. `quality_lab`（medium/low 两档，需两次）
4. `variant_lab`
5. 新建法线/高光场景
6. `character`（最后，负载最高）

## 五、判读标准

每张图必须能回答「这个参数改了之后画面上哪里变了」，答不上来就不算验证通过。历史上有三次把"测试设计问题"误判成"实现问题"（白光测受光、高频噪声测 LOD、条纹贴图被 UV 拉伸），遇到看不出差异时**先用探针排除绑定问题**，再怀疑实现。
